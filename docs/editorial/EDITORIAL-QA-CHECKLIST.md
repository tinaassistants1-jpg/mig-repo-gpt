# Контрольный список редакции

**Для чего:** финальная проверка текста перед сдачей. Список проходится полностью;
пропущенный пункт отмечается как пропущенный, а не как пройденный.
**Связано с:** `MIG-EDITORIAL-STANDARD.md`, разделы 4, 8, 9.

## Порядок работы

1. **Перерыв перед корректурой.** Корректура не делается сразу после редактуры: свой текст
   глаз «досказывает». Если перерыв невозможен (одна рабочая сессия, ИИ-редактор),
   корректуру делает другой исполнитель или она проводится как чтение с нуля: без исходника
   и без карты правок перед глазами.
2. **Один тип ошибок за проход** (UNC Writing Center, Editing and Proofreading). Проход
   «на всё сразу» пропускает мелочи — так прошло «о участии».
3. **Сначала механика, потом чтение.** Машина ищет то, что глаз пропускает; человек — то,
   что машина не видит.
4. **Новый текст отдельно.** Всё, чего не было в исходнике, проверяется вторым проходом
   по карте правок или диффу.
5. **Текст в чате — тоже текст.** Редакция, которую отдают сообщением в чате, а не файлом,
   перед отправкой сохраняется во временный файл и проходит механические проверки.
   «О участии» ушло к заказчику именно в чате, где проверок не было.

## Проход 0. Механические проверки

Текст сохраняется в файл `text.md` (UTF-8). Команды для Linux; на macOS — GNU grep
(`ggrep -P`).

**Обязательно задать UTF-8-локаль.** Без неё `grep -P` читает байты, а не буквы, и проверки
молча ничего не находят. Это выяснилось на тестовом прогоне 29.10.2026: строка
«о участии» не была найдена, пока локаль не задали.

```bash
export LC_ALL=C.UTF-8

# 0. Контрольный тест: команда 1 обязана вывести эту строку. Не вывела — проверки не работают
printf 'о участии\n' | grep -P '(?<!\p{L})[Оо] (?=[аиоуыэАИОУЫЭ])'

# 1. «о» перед гласной: должно быть «об» (кроме е, ё, ю, я: «о ёлке», «о юге»)
grep -nP '(?<!\p{L})[Оо] (?=[аиоуыэАИОУЫЭ])' text.md

# 2. Предлоги перед «мне», «всём», «всех»: «обо мне», «обо всём», «со мной», «ко мне»
grep -nP '(?<!\p{L})(о|с|к) (мне|всём|всех|всем|всей|всего)(?!\p{L})' text.md

# 3. Удвоенные слова: «в в», «и и»
grep -nP '(?<!\p{L})(\p{L}+) \1(?!\p{L})' text.md

# 4. Плейсхолдеры и пометки редактора: в публикационной редакции должно быть пусто
grep -nP '\[|\]|TODO|уточн|будет указан|будут указан|будут опубликован' text.md

# 5. Двойные пробелы и пробел перед знаком препинания
grep -nP '  |\s[,.;:!?»)]' text.md

# 6. Дефис вместо тире между словами
grep -nP '\p{L} - \p{L}' text.md

# 7. Смешение «е» и «ё» в одном имени или слове: вывести слова с «ё» и сверить вручную
grep -oP '\p{L}*[ёЁ]\p{L}*' text.md | sort | uniq -c

# 8. Все числа, цены и даты: распечатать и сверить с материалами построчно
grep -noP '\d[\d  .,–-]*\s?(€|₽|%|лет|года|год|января|февраля|ноября|декабря)?' text.md

# 9. Частота шаблонов: антитезы (включая форму «Не X. Y.» в начале предложения) и вопросы.
#    Повелительное «Не мешайте» тоже попадёт в вывод — это подсказка для подсчёта, не ошибка
grep -noP '(?<!\p{L})(не просто|не только|а не)(?!\p{L})|(?:^|[.!?…]\s+)Не (?!только|просто)\p{L}+' text.md
grep -c '?' text.md

# 10. Числительное + слово-процесс: «шесть длительных терапий», «две работы».
#     Процесс обычно не считают штуками; проверить естественность (стандарт, 4.1)
grep -nP '(?i)(?<!\p{L})(два|две|три|четыре|пять|шесть|семь|восемь|девять|десять|\d+)\s+(\p{L}+(ых|ые|их|ие)\s+)?(терапи[йиюя]|работ(?!\p{L})|процесс(ов|а)|взаимодействий|консультаций)(?!\p{L})' text.md

# 11. Канцелярит по Норе Галь: три и больше отглагольных существительных в строке.
#     Подсказка, а не приговор: названия докладов и цитаты не правятся.
#     Строки-перечни тем («На разборе: …») пропускаются: они именные по жанру
perl -Mutf8 -CSD -ne 'next if /^На разборе:/; my @m = /(?<!\p{L})(\p{L}{3,}(?:ание|ания|анию|анием|ании|аний|ение|ения|ению|ением|ении|ений|ация|ации|аций))(?!\p{L})/gi; print "$.: ".scalar(@m)." — @m\n" if @m>=3' text.md
```

Проверки 10 и 11 проверены на тестовых строках 29.10.2026: проверка 10 находит
«Шесть длительных терапий» и не срабатывает на «Десять лет терапии»; проверка 11 находит
«Проведение разбора осуществляется с целью повышения эффективности формирования понимания».
Первая версия проверки 11 учитывала слова на «-ость» и на тексте Р2 дала 11 срабатываний,
почти все ложные: «близость», «телесность» — не отглагольные существительные, а перечни
тем — не повествование. После сужения — одно срабатывание, и оно по делу.

Пустой вывод команд 1–6 — норма. Любая строка в выводе разбирается вручную: возможны
ложные срабатывания (например, междометие «О» или «о» в цитате, которую нельзя править).

## Проход 1. Уровень A: факты и логика

- [ ] Каждое имя, регалия, название доклада сверено с материалами **посимвольно**
      (буква «ё», дефисы, кавычки внутри названий).
- [ ] Каждая цена и дата сверена с тарифной сеткой; дедлайны не истекли к дате публикации.
- [ ] Пересчитаны все количественные утверждения на странице (случаи, доклады, спикеры, дни).
- [ ] Каждому фактическому утверждению присвоен статус (стандарт, раздел 5); в публикационной
      редакции нет «гипотез» и «требует проверки».
- [ ] Для каждого риторического вопроса и обобщения выписана предпосылка; предпосылка верна
      (`AI-WRITING-ANTI-PATTERNS.md`, 3.4).
- [ ] Все «поэтому», «из-за», «значит» имеют основание.
- [ ] Интерпретации клиентских случаев атрибутированы или поданы вопросом, а не как факт.
- [ ] Статус организации, членство, аккредитация, сертификат — каждое слово подтверждено;
      сертификат не связан с организацией, которая его не выдаёт.
- [ ] Нет противоречий: первый экран ↔ программа ↔ тарифы ↔ FAQ (одинаковые цифры, состав,
      условия).
- [ ] В тексте нет возможностей продукта, которых нет в материалах (пример ошибки:
      «можно участвовать с телефона»).

## Проход 2. Уровень B: русский язык

Каждый подпункт — отдельный проход.

- [ ] Орфография: чтение **с конца**, по словам — так глаз не досказывает смысл.
- [ ] Пунктуация: обвести взглядом каждый знак; тире, двоеточия, запятые в оборотах.
- [ ] Предлоги и управление: результат механических проверок 1–2 разобран.
- [ ] Сочетаемость и счётность: каждый заголовок и каждое новое словосочетание проверены
      вопросом «сказал бы это коллега вслух?» (стандарт, 4.1).
- [ ] Повторы: однокоренные слова в соседних предложениях; слово из заголовка в первой фразе.
- [ ] Термины: «супервизия», «интервизия», «разбор», «перенос», «альянс», «ретрофлексия»
      употреблены в своём значении.
- [ ] Чтение вслух: каждую фразу произнести так, как её сказал бы образованный человек,
      а не диктор рекламы. Где запнулся — переписать.
- [ ] Отглагольные существительные: вывод проверки 11 разобран; где возможно, глагол
      вместо существительного (Нора Галь, «Жечь или сушить?»).
- [ ] «Алгебраические значки» («ситуация», «момент», «формат», «пространство», «процесс»,
      «опыт», «работа» без дополнения): на место каждого попробовать подставить конкретное
      значение (Нора Галь, «Словесная алгебра»).
- [ ] В каждой фразе длиннее 25 слов находится логическое сказуемое с первого чтения
      (Нора Галь, «Туманы…»).
- [ ] Пунктуация в заголовках выбрана по смыслу: точка разделяет утверждения, тире
      связывает, двоеточие раскрывает. Тире не удаляются механически (Розенталь,
      «Справочник по пунктуации», предисловие).

## Проход 3. Уровень C: литературное качество

- [ ] У каждого абзаца есть сведение, которого нет в соседних.
- [ ] Нет серий одинаково построенных предложений и разделов.
- [ ] Частота приёмов в норме (`AI-WRITING-ANTI-PATTERNS.md`, раздел 2).
- [ ] Каждая удалённая выразительная фраза прошла тест на категорию; категории 3 и 4
      не удалены.
- [ ] Для каждого спорного приёма определено, что в нём есть: выразительность,
      убедительность, искусственность (`AI-WRITING-ANTI-PATTERNS.md`, раздел 4). Удаляется
      только то, в чём есть искусственность и нет первых двух свойств.
- [ ] Каждая метафора проверена на цельность образа при буквальном прочтении.
- [ ] Описания клиентских историй прочитаны на такт: нет сенсационности, иронии над
      страданием, «красивостей» поверх боли.
- [ ] Каждая удаляемая фраза проверена на сильное ядро; удаляется только слабая часть.
- [ ] Каждая конкретизация абстрактного слова проверена: значение одно, известно и не беднее.
- [ ] Выразительные детали не объяснены там, где читатель поймёт их сам.
- [ ] Литературная экспертиза по вопросам стандарта, раздел 14, проведена хотя бы для первого
      экрана, карточек и финала: что читатель получает первым и последним, куда движется
      напряжение.
- [ ] Сравнение с исходником: не стал ли текст ровнее и беднее. Список возвращённых
      авторских мест записан в протокол.
- [ ] Повторы между разделами разобраны по правилу «шум или усиление» (стандарт, раздел 7).

## Проход 4. Уровень D: маркетинговая эффективность

Полная версия — `COMMERCIAL-COPY-PROTOCOL.md`, раздел 10. Ниже — минимум для сдачи.

- [ ] Первый экран за пять секунд отвечает: что, для кого, когда, чем отличается, сколько стоит.
- [ ] Первый экран оценивается целиком: заголовок, подзаголовок и кнопка вместе. Метафора
      в заголовке допустима, если следующая строка называет формат буквально.
- [ ] Для заголовка рассмотрено не меньше десяти вариантов с разными содержательными
      подходами; оценки записаны в протокол.
- [ ] Причина выбрать продукт подтверждена программой.
- [ ] Список возражений составлен; у каждого есть ответ или запись в открытых вопросах.
- [ ] У каждого тарифа понятен состав и отличие от соседнего.
- [ ] Ни одной кнопки покупки у тарифа без утверждённого состава.
- [ ] Призыв к действию стоит после программы и после тарифов.
- [ ] Нет фальшивой срочности и дефицита.
- [ ] Ни одно утверждение о конверсии не выдано за проверенное.

## Проход 5. Уровень E: приёмка

- [ ] Текст прочитан заново целиком, без исходника перед глазами.
- [ ] Каждый новый фрагмент (которого не было в исходнике) прошёл проходы 1 и 2 повторно.
- [ ] Решения аудита выполнены в публикационной редакции (что сказано «снять» — снято).
- [ ] Механические проверки 1–6 повторены на финальном файле.
- [ ] Оценки по шкале выставлены с доказательствами; блокеры перечислены.
- [ ] Присвоен статус: рабочая редакция / публикационная, заблокирована / готово к публикации.
- [ ] Публикационная редакция и протокол сданы **отдельными** результатами.
- [ ] В журнал ошибок записаны новые типы ошибок, если они найдены.

## Личный список типовых ошибок редакции

Пополняется из `EDITORIAL-ERROR-LOG.md`. Перед сдачей — отдельный поиск по каждому пункту.

| Типовая ошибка | Как искать |
|---|---|
| «о» перед гласной | механическая проверка 1 |
| неестественная счётность («терапии» как единицы) | проход 2, сочетаемость заголовков |
| ложная предпосылка в вопросе | проход 1, выписать предпосылки |
| интерпретация как факт | проход 1, все описания клиентов |
| придуманная возможность продукта | проход 1, сверка FAQ с материалами |
| удаление сильного места ради борьбы с маркерами | проход 3, сравнение с исходником |
| плейсхолдер или кнопка в «финальном» тексте | механическая проверка 4, проход 4 |
| категоричный юридический вывод | протокол: каждое «нужно» про право заменено на тип из стандарта, раздел 6 |
| противоречие между протоколом и текстом | проход 5, решения аудита |
