# LeadBot — телеграм-бот приёма заявок

Бот задаёт клиенту пять вопросов, сохраняет заявку в базу и сразу уведомляет
менеджера. Менеджер работает с заявками прямо в Telegram: смотрит список,
меняет статусы, выгружает всё в CSV.

Стек: **Python 3.11 · aiogram 3 · SQLAlchemy 2 (async) · Alembic · PostgreSQL · Redis · Docker**.
Интерфейс бота полностью на русском.

---

## Как это работает

### Клиент

```
/start
  └─ 📝 Оставить заявку
       ├─ 1/5 услуга          (кнопки: сайт, веб-приложение, бот, дизайн, автоматизация, другое)
       ├─ 2/5 бюджет          (кнопки: 5 диапазонов)
       ├─ 3/5 описание задачи (текст, 10–2000 символов)
       ├─ 4/5 имя             (2–64 символа)
       ├─ 5/5 контакт         (кнопка «Поделиться номером» либо телефон / e-mail / @username)
       └─ подтверждение → заявка в БД + уведомление менеджеру
```

На любом шаге работает `/cancel`. Некорректный ввод не пропускается: шаг
повторяется с подсказкой, что именно не так.

### Менеджер

| Команда | Что делает |
|---|---|
| `/admin` | Справка по админ-командам |
| `/leads [статус]` | Последние 10 заявок, можно отфильтровать: `new`, `in_work`, `done`, `rejected` |
| `/lead_info <id>` | Карточка конкретной заявки |
| `/status <id> <статус>` | Сменить статус, например `/status 12 in_work` |
| `/stats` | Сводка: всего заявок, пользователей, разбивка по статусам |
| `/export` | Выгрузка всех заявок в CSV (UTF-8 с BOM — Excel открывает без плясок) |
| `/audit` | Последние записи журнала действий |

Доступ определяется списком `ADMIN_IDS`. Посторонний, отправивший админ-команду,
получает отказ, а не молчание.

## Быстрый старт

### Вариант 1 — Docker (рекомендуется для сервера)

```bash
cp .env.example .env
# впишите BOT_TOKEN и ADMIN_IDS
make up          # docker compose up -d --build
make logs        # docker compose logs -f bot
```

Поднимаются три контейнера: `bot`, `postgres`, `redis`. Миграции накатываются
автоматически при старте (`docker-entrypoint.sh`).

### Вариант 2 — локально, без Docker

```bash
python -m venv .venv && source .venv/bin/activate
make install                     # pip install -e ".[dev]"
cp .env.example .env
# в .env: DATABASE_URL=sqlite+aiosqlite:///./leadbot.sqlite3 и пустой REDIS_URL
make migrate                     # alembic upgrade head
make run                         # python -m bot
```

Без Redis состояния диалогов хранятся в памяти и теряются при рестарте —
для разработки нормально, для прода нет.

### Где взять значения для .env

- `BOT_TOKEN` — у [@BotFather](https://t.me/BotFather), команда `/newbot`.
- `ADMIN_IDS` — числовой ID пользователя, например у [@userinfobot](https://t.me/userinfobot).
- `NOTIFY_CHAT_ID` — необязательный. Если задан, уведомления идут в этот чат
  (например, в группу отдела продаж), иначе — в личку каждому из `ADMIN_IDS`.
  Для группы бота нужно добавить в неё, а ID группы отрицательный.

## Структура проекта

```
bot/
├── __main__.py        точка входа: сборка приложения и long polling
├── config.py          настройки из окружения (pydantic-settings)
├── catalog.py         справочники услуг и бюджетов
├── texts.py           все тексты бота
├── keyboards.py       клавиатуры и callback-данные
├── states.py          состояния FSM
├── filters.py         фильтр доступа IsAdmin
├── handlers/          common · lead · admin · errors
├── middlewares/       база данных · антифлуд · журналирование
├── services/          уведомления · выгрузка CSV
├── db/                модели · движок · репозиторий
└── utils/             валидаторы ввода
migrations/            Alembic
tests/                 60 тестов
scripts/backup_db.sh   резервная копия базы
```

Роутеры собираются **фабриками** (`build_router()`), а не создаются на уровне
модуля: aiogram запрещает подключать один и тот же `Router` дважды, а фабрика
позволяет каждому тесту получить свежее дерево хендлеров.

Вся работа с БД — в `db/repo.py`. Хендлеры SQL не пишут, поэтому логику
запросов можно тестировать отдельно от Telegram.

## Безопасность

- Секретов в коде нет: всё через переменные окружения, `.env` в `.gitignore`.
- Контейнер работает от непривилегированного пользователя `botuser` (uid 10001),
  не от root.
- Ввод пользователя экранируется перед отправкой (`parse_mode=HTML`), поэтому
  разметку в заявке подделать нельзя.
- Валидация всех текстовых полей: длина, формат контакта, управляющие символы.
- Антифлуд: не чаще одного апдейта в `THROTTLE_RATE` секунд на пользователя.
- Админ-команды закрыты фильтром `IsAdmin` на уровне роутера — забыть повесить
  его на отдельный хендлер невозможно.

## Журналирование

Два уровня.

**Технический лог** (stdout, попадает в `docker compose logs`) — каждый апдейт:

```
2026-09-07 12:00:01 | INFO | leadbot.updates | кто=200000002 (@client) | что=message: /start | хендлер=cmd_start | результат=ok за 12 мс
```

**Журнал действий** в таблице `audit_log` — что именно изменилось в данных:
кто (`actor_id`), в какой роли (`actor_role`), какое действие (`action`),
над чем (`target`), с каким результатом (`result`). Пишутся старт диалога,
создание заявки, смена статуса и выгрузка. Читается командой `/audit`.

## Резервные копии

```bash
make backup          # ./scripts/backup_db.sh
```

Кладёт сжатый дамп в `backups/` и удаляет копии старше 14 дней
(`KEEP_DAYS`). Для регулярности — в cron:

```
0 3 * * * /path/to/scripts/backup_db.sh >> /var/log/leadbot-backup.log 2>&1
```

## Разработка

```bash
make test        # pytest
make lint        # ruff check
make fmt         # ruff format + автофиксы
make revision M="описание"   # новая миграция после правки моделей
make migrate     # накатить миграции
```

Тесты гоняют настоящий `Dispatcher` с подменённой Telegram-сессией
(`tests/conftest.py`) и SQLite в памяти — сеть и токен не нужны. Покрыт весь
путь заявки: от `/start` до записи в базе и уведомления менеджеру.

CI (GitHub Actions) на каждый push: линтер, форматирование, тесты, накат и
откат миграций, сборка Docker-образа.

## Что можно добавить дальше

- Вебхуки вместо long polling (нужен домен и TLS) — заметно экономит ресурсы
  на больших нагрузках.
- Интеграция с CRM (amoCRM / Битрикс24) вместо CSV.
- Кнопки смены статуса прямо в уведомлении менеджеру.
- Мультиязычность: тексты уже вынесены в `bot/texts.py`, потребуется только
  словарь на второй язык и выбор языка в `/start`.
